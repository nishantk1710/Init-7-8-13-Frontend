## Column meanings

- **Live rows** — what `$count` returned on the last discovery sweep. `unknown` means
  `$count` itself errors, so the row total is genuinely not knowable without a full read.
- **$count** — `counted` asks SAP for a total; `fallback` never asks, and pages until a
  short page; `auto` tries once and demotes itself, so a set self-promotes when SAP fixes it.
- **Extract** — `filtered-only` sets refuse an unfiltered read outright. They are far too
  large to pull whole (§1.4).
- **Serving** — `mock` means the app is fed from generated fixtures; `live` means real CPI.
  This is the dial in `src/lib/sap/routing.ts`. Flip one set at a time, running
  `npm run smoke:cpi` after each.

## Flipping a set to live

1. Add it to `SET_SOURCES` in `src/lib/sap/routing.ts` as `"live"`.
2. Run `npm run smoke:cpi`. A failure names the step.
3. Check the set's blocker column first — a set that returns zero rows will render an
   honest empty state, not an error, and that may not be what you want in a demo.

**Flip the zero-row sets LAST.** Their schema is live but they hold no data, so moving
them early trades working synthetic data for a legitimately empty screen.
